Reflecting on the process of developing this full stack web application has been an insightful journey. From designing the architecture to implementing functionality and ensuring robust security, this project has truly encompassed a wide range of skills and concepts.

Architecture
In terms of frontend development, I utilized a combination of Express HTML, JavaScript, and a single-page application (SPA) framework. Each of these approaches has its own strengths. Express HTML provided a straightforward way to render server-side content and was particularly useful for serving static pages efficiently. JavaScript allowed for dynamic client-side interactions, enhancing user experience through responsive design elements. The SPA framework, however, took this a step further by providing a seamless user experience without the need to reload pages. This was particularly beneficial for the administrative side of the application, where quick transitions between different views and tasks were essential. Comparing these, while Express HTML is great for simple, static content, the SPA approach was superior for creating a fluid and interactive user experience.

On the backend, I opted for a NoSQL MongoDB database. This decision was driven by the flexibility MongoDB offers, especially in handling unstructured data. MongoDB's schema-less nature allowed me to iterate quickly on the database design without being locked into a rigid schema structure. This flexibility was crucial for accommodating the varying data needs of both the customer-facing and administrative sides of the application.

Functionality
JSON played a pivotal role in tying together the frontend and backend of the application. Unlike JavaScript, which is a scripting language used to create dynamic content, JSON is a lightweight data format that is easy to read and write. JSON allowed me to seamlessly exchange data between the frontend and backend, ensuring that the data was structured and transmitted efficiently. This was particularly useful in the SPA, where data needed to be updated dynamically without a full page reload.

Throughout the project, I found myself refactoring code several times to improve functionality and efficiency. One example was optimizing the user interface (UI) components to be reusable across different parts of the application. By creating modular components, I not only reduced redundancy in the code but also made it easier to maintain and update the UI. The benefits of this approach were clear: it sped up development, made the codebase more organized, and improved the overall user experience by ensuring consistency across different parts of the application.

Testing
Testing the various endpoints of the API was another critical part of the process. Each method—whether it was a GET, POST, PUT, or DELETE request—required careful testing to ensure that data was being correctly handled and returned by the server. Adding security layers, such as authentication for the admin login, introduced additional complexities in testing. I had to ensure that not only were the endpoints functioning correctly but that they were also secure against unauthorized access. This involved testing for vulnerabilities such as SQL injection, ensuring that the application was robust and secure.
